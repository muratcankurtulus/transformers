The most consequential findings are:

1. **The tokenizer’s byte IDs overlap with its special-token IDs.** Both use IDs 0–3. This breaks lossless decoding: my check turned `\x00A\x01B\x02C\x03D` into `ABCD`. Four other IDs are undefined. Reserve separate ID ranges, regenerate tokenized data, and explicitly manage checkpoint compatibility. See tokenizer initialization (src/tokenizer.py:20).
1. **Encoder–decoder cross-attention reverses queries and keys.** The decoder should supply queries and the encoder should supply keys and values. Your code fails when source and target lengths differ; matching lengths can conceal the incorrect operation. Fix the argument order and test unequal lengths. See the attention call (src/blocks.py:278).
1. **The encoder–decoder mask and output softmax are incorrect.** Its floating-point mask fails in `masked_fill_`, and its diagonal would block tokens from attending to themselves. The final softmax omits its dimension; in my batch-size-one check, every output became exactly `1.0`. Use the correct boolean causal mask and return raw logits for training. See mask creation (src/transformer.py:19) and decoder output (src/blocks.py:378).
1. **Position handling needs repair.** The sinusoidal formula uses incorrect frequencies. Selecting RoPE still adds sinusoidal positions. RoPE rejects BF16 inputs, promotes FP16 inputs to FP32, and creates CPU positions when extending its cache. Implement consistent positional choices and device-aware, mixed-precision-safe rotation. See position encodings (src/blocks.py:28).
1. **An epoch processes much more text than its name suggests.** Every possible token position starts a training window. With a 256-token context, interior tokens appear approximately 256 times per epoch. That can be an intentional sampling strategy, but it is expensive and makes epoch counts misleading. Use packed blocks or a defined random-sampling budget, and report processed tokens separately from corpus size. See dataset construction (src/train_gpt.py:38).
1. **FlashAttention is a dependency, but the implementation does not use it.** Attention explicitly builds the full token-by-token matrix. Move to PyTorch SDPA, verify kernel dispatch on your GPU, and carefully translate mask semantics and evaluation dropout. Mixed precision and compilation are further opportunities after the correctness fixes. [PyTorch SDPA documentation](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html).
1. **Checkpointing does not support reliable generation or training restart.** Generation hard-codes an architecture different from training defaults. Checkpoints omit configuration, tokenizer identity, optimizer state, and progress. Save those together, reconstruct the model automatically, and test interrupted versus uninterrupted training. See generation setup (src/generate.py:18) and checkpoint saving (src/train_gpt.py:140).
1. **Distributed training is absent.** Four DataLoader workers prepare data for one training process; they do not train on four GPUs. You need process initialization, local device selection, synchronized gradients, partitioned data, global validation metrics, effective-batch accounting, and coordinated checkpoints. Start with DDP and verify a tiny two-rank update against an equivalent single-process update.
